Silver 0.7.0 — One Good Step

Design work happens one step at a time now. A skill runs, its checks actually
run, the result says what is true, and you choose what happens next.

## Install

```sh
npx --yes silver-design-framework@0.7.0 setup inspect . --json
```

Requires Node.js 20.11 or newer. Do not run `npx silver`; an unrelated package
holds that name.

Existing workspaces upgrade with a reviewable migration:

```sh
.silver/bin/silver migrate .            # preview
.silver/bin/silver migrate . --apply
```

## Why this release exists

A real session took `0.6.1` from `npm install` through brand, design system, and
a Vite prototype. It finished, but it needed manual manifest edits, two repair
runs, recovery from a half-applied invocation, a second nested `npm install`,
and moving `node_modules` out of the workspace to get checks to pass. Twenty-two
issues came out of it. Most trace back to three.

**Checks were never run.** The scaffold prefilled every required check as
`not-run`, and the runtime believed whatever the request claimed. A prototype
result reported six passing checks while `.silver/results/checks/` did not
exist — including a browser interaction check that could not have run, because
the browser never reached the prototype. Downstream work stayed `not-ready`
forever, and `what-now` kept recommending work that was already done.

**A failure after the first write was a dead end.** Outputs landed, the Git
checkpoint failed, and the identical retry was refused for overwriting the files
the failed attempt had just created.

**Nothing told the agent to stop.** The rule that a leaf skill runs only itself
lived in `docs/`, which never ships into a workspace, while the README presented
the design loop as a ten-step chain. So brand ran into system ran into
prototype, unattended, and the first reviewable moment was an hour later.

## Invocations that tell the truth

- A guarded invocation runs its own required checks and writes their evidence.
  Nothing to run first, nothing to copy back in.
- A claimed `pass` is believed only when its evidence file exists and agrees.
  Otherwise it is recorded as `not-run` with the reason.
- `complete-awaiting-verification` is a distinct state: nothing is wrong, but a
  required check could not run, so the work is unverified rather than confirmed.
  Blocked browser checks land here instead of looking verified.
- Persisting a result is declared and observed as the write it is. `what-now` is
  genuinely read-only now — `--record` is opt-in, and setup uses it once.
- Duplicate effect declarations are removed before a result is persisted.

## Accepted work activates everywhere at once

Accepting a canonical artifact updates the artifact, `design/manifest.yaml`,
`design/INDEX.md`, and `.silver/lock.yaml` in one invocation and commits them in
one checkpoint. The manifest edit is surgical, so flipping one status is a
one-line diff rather than a reformatted file.

`silver repair` and the migration reconcile a workspace that already disagrees
with itself, which is what an existing 0.6 workspace needs.

## Recoverable invocations

An accepted invocation confirms Git can commit *before* touching canonical
files, and refuses with nothing written when it cannot. If something fails after
outputs land, Silver writes a resumable request with fresh integrity hashes and
prints the exact retry command.

## One step at a time

Generated `AGENTS.md` and `CLAUDE.md` now say it outright: run one skill, report
what its checks said, offer two or three next moves, and wait. Recipes and
implementation profiles are `offered` rather than selected. Playbooks honour
`autonomy.mode: single-step`, which the shipped loop declares, so a composed run
cannot advance five skills between checkpoints.

## My Practice is where your preferences live

One visible, Git-tracked folder, applying to every workspace you work in.
Nothing personal is authored inside a project, because a project is shared.

Two things resolve from there now:

- **`studio-voice.md`** — how the agent talks while designing. Silver ships a
  default register; yours replaces it. This is a layer of its own, separate from
  what the skills do, so skills stay precise and upgradeable without touching
  tone, and tone changes never edit twenty-one files.
- **`methods/*.yaml`** — method overlays. The `silver/method-overlay/v1`
  contract has existed since 0.5 with **nothing reading it**: you could write
  preferred questions, techniques, quality emphasis, and exclusions and no agent
  would ever see them. They are now loaded, validated, and applied.

Silver seeds both files commented out when it creates your practice, so the
override points are discoverable — and inert until you mean them. An invalid
overlay is reported by `silver doctor` rather than silently ignored.

Preferences are carried into a workspace as an untracked `.silver/my-practice.md`
that Silver adds to `.gitignore`. It is a generated copy; editing it does nothing
lasting. Personal preference adds to how work is done and never relaxes project
facts, guardrails, required guidance, or approval boundaries.

## Fixes

- Design checks skip `node_modules`, `dist`, `build`, `.vite`, and other
  dependency, build, and cache directories. Third-party raw colors are not your
  workspace's findings.
- The generated launcher resolves the CLI relative to the workspace instead of
  hard-coding an absolute path, so a workspace survives being moved, cloned, or
  checked out by another user. Windows launchers no longer carry POSIX paths.
- `what-now` inspects a directory-backed component catalog as a directory. Fresh
  workspaces no longer report themselves broken.
- `doctor` validates `design/assets/catalog.json` and
  `design/presentation-kit/kit.json` against their schemas instead of warning
  that they lack Markdown frontmatter. A new workspace produces zero
  diagnostics.
- Adapter skills are advertised as `silver-<id>`, so generic names like `system`
  and `map` cannot be shadowed. Canonical `.skills/<id>` paths and contract ids
  are unchanged.
- `allowed-tools` advertises only the launcher. Direct script execution that
  could not resolve its dependencies is no longer offered.
- Setup questions carry plain-language explanations, per-option effects,
  external paths, and reversibility — including that My Practice lives outside
  the project, and that Git is worth having before hundreds of files exist.
- Setup states the reference system's separate `npm install` step.
- A new workspace's manifest describes the workspace instead of inheriting
  "Blank-workspace fixture for The Silver Design Framework".
- Installing the package prints the safe next command.
- Runnable prototypes ship a `NOTES.md` with the directory, install step, run
  command, and expected URL.
- New: `silver check [--only <ids>]` runs the fast suite and writes evidence.

## Compatibility

Skill contracts, the guardrail registry, providers, and the default playbook
move to `0.7.0`. `silver/skill-result/v2` gains `pending_outputs`,
`resume_request`, a per-check `reason`, and the
`complete-awaiting-verification` execution status. `silver/setup-plan/v1` gains
structured `questions`. The manifest's implementation profiles gain `status`.

`npm run build` passes 99 tests; `npm run test:package` passes for the exact
release archive.
