Silver 0.6.1 — npm channel

Adds npm as the primary distribution channel. There are no behaviour changes to
skills, contracts, checks, or the workspace format.

## Install

```sh
npx --yes silver-design-framework@0.6.1 setup inspect . --json
```

No npm account, login, or registry token is needed. If your network cannot reach
the registry, the same artifact is attached to this release:

```sh
npx --yes https://github.com/thejparsenault/silver-design-framework/releases/download/v0.6.1/silver-design-framework-0.6.1.tgz setup inspect . --json
```

Requires Node.js 20.11 or newer. Do not run `npx silver`; an unrelated package
holds that name.

## Why this release exists

`0.6.0` shipped as an immutable GitHub release before the npm channel was
prepared, so the artifact published under that tag pins the release tarball URL
in every workspace launcher it generates. That artifact is self-consistent and
keeps working: the URL it points at is immutable and will not move. It simply
predates npm.

Publishing different bytes to npm under the same `0.6.0` version would have left
one version number naming two artifacts with different behaviour, which is
exactly what immutable releases exist to prevent. `0.6.1` is the first version
published to both channels from identical bytes.

## What changed

- The generated `.silver/bin/silver` launcher pins the published package spec
  rather than a release tarball URL when Silver was installed ephemerally. The
  registry checks integrity on every re-fetch, published versions are immutable,
  and corporate npm proxies can mirror it.
- `installer/version.mjs` derives the package spec, release tag, artifact name,
  and download URL from a single version constant so the two channels cannot
  drift apart.
- `npm run release` runs both gates, writes the artifact and its checksum to
  `dist/`, and prints the publish and verification commands for both channels.
- `package.json` declares `publishConfig.access` as public and no longer sets
  `private`.

## Upgrading from 0.6.0

```sh
silver migrate /path/to/workspace          # preview
silver migrate /path/to/workspace --apply
```

The migration regenerates the launcher for however the CLI is now delivered and
preserves project-owned work. Existing 0.6.0 workspaces keep working untouched;
their launchers resolve through the immutable 0.6.0 release asset.

## Fixes

- `installer/tests/package-smoke.mjs` relied on `npm install --prefix` creating
  its consumer directory. That only holds outside an npm lifecycle script;
  nested under one, inherited npm config left it uncreated and the install
  failed. It now creates the directory explicitly.
- `prepublishOnly` no longer runs the packaged smoke, because nesting an
  `npm pack` inside an `npm publish` is fragile by construction. The full
  packaged gate stays in `npm run release`.

## Verification

`npm run build` passes 91 tests. `npm run test:package` passes for this exact
archive. `npm publish --dry-run` resolves to `silver-design-framework@0.6.1`
with public access.
