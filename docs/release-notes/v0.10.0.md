# Silver 0.10.0 — One Provenance Model

This release unifies how every dependent artifact and every playbook run
records what it was built from. Before 0.10.0, "provenance" meant four
different things depending on which kind you were looking at:
`working-artifact.sources[]` (the only real citation list), prototype's
informal, unschemaed `inputs:` (never validated), presentation-kit's
`source_revisions[]` (identical shape, different name), and skill-invocation/
skill-result/playbook-state's `inputs[]` (a different concept entirely). Maps
and structures had no citation list at all. Two enforcement rules also forced
a working-artifact's `sources[]` to exactly equal its producing invocation's
`inputs[]`, which produced false-positive "sources disagree" findings on real
workspaces — the two answer genuinely different questions and were never
meant to match.

Every dependent artifact kind — `working-artifact`, `prototype`, `map`,
`structure`, and `presentation-kit` — now records `sources[]` the same way:
an immutable, accumulate-on-new-citation record of what that revision was
authored from, verified for accuracy once at write time and never re-checked
for staleness afterward. Primary sources (brand, product, voice,
design-principles, reference-collection) and indexes (`design-context`) are
unaffected — they were never citation-bearing to begin with.

Playbooks and skill invocations get the same field name, `sources[]`, for
consistency, but a different meaning: the *latest* thing a run or node
observed, overwritten each time it re-runs, not accumulated. No equality is
enforced between an artifact's `sources[]` and an invocation's `sources[]` —
they answer different audit questions.

Targeting 0.10.0 rather than 1.0.0: this is a breaking schema change, not a
stability commitment. SemVer's major-version-zero clause permits breaking
changes without a major bump, and the schema is still being actively
discovered.

## Changes

- **`sources[]` replaces informal or missing citation lists.** `prototype`,
  `map`, and `structure` gain a real, schema-validated `sources[]`
  (`map`/`structure` additively; `prototype` folds in the old `flow_refs`).
  `presentation-kit.source_revisions[]` is renamed to `sources[]` — same
  shape, no data change.
- **Prototype metadata moves from YAML to JSON**, matching every other
  artifact kind (`prototype.yaml` → `prototype.json`). No prototype in the
  wild used YAML-specific syntax (comments, block scalars), so nothing is
  lost in the conversion.
- **Flow revisions are strings, like everywhere else.** `flow.schema.json`'s
  `revision` was the one holdout still using a bare integer; it now uses the
  shared `r${n}`/content-hash/semver string format.
- **The `sources`-must-equal-`inputs` enforcement rule is gone**, along with
  `prototype.flow-revision-mismatch` and the render-time flow-pin check it
  was built on. A citation is a permanent fact about the revision that made
  it, not a live claim — nothing re-validates it after the fact, the same way
  working-artifact sources already worked.
- **Write-time validation is now generic.** Every kind's `sources[]` is
  checked for current accuracy the moment it's written, not just
  working-artifact's.
- **Playbook and invocation `inputs[]` is renamed to `sources[]`** on
  `skill-invocation`, `skill-result`, and `playbook-state` (including its
  per-node state), documented as a distinct, overwrite-per-run concept from
  an artifact's own `sources[]`. The abstract, contract-level `inputs`
  declarations on `skill`/`playbook` (kind/required/role, not a citation) are
  unchanged.
- **`what-now` can surface drift as a suggestion.** A prototype, map,
  structure, or working-artifact whose cited source has since moved gets a
  named, non-blocking recommendation — never a check failure.

## Upgrading

Run `silver migrate . --apply` on any existing workspace. It converts
`prototypes/*/prototype.yaml` to `prototype.json` with a populated
`sources[]`, backfills `sources: []` on existing maps and structures, renames
`presentation-kit`'s `source_revisions` key, and converts any remaining
integer flow revisions to the string format. `silver check` should no longer
report `artifact-sources-disagree` or `flow-revision-mismatch` findings
afterward.
