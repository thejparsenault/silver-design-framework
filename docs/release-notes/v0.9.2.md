# Silver 0.9.2 — One Representation Model

This corrective release completes the representation-contract transition that
0.9.0 began. New linked-source and Figma synchronization now use the v2 binding,
change-set, result, and provider-operation contracts from inspection through
application. Historical v1 reconciliation records remain readable evidence,
but live v1 bindings must be migrated and inspected again before they can sync.

## Fixes

- **Representation checks understand v2 records.** Revision pins, synchronization
  states, semantic mapping, proposal freshness, and authority are evaluated from
  their v2 fields. Healthy initialized, uninitialized, and missing identities no
  longer produce false findings.
- **Proposal freshness is real again.** Pending proposals check every actionable
  operation even before a selection exists, including target absence, local
  sources, linked-source targets, and provider captures. Applied results are not
  compared against their intentionally pre-application identities.
- **There is one live reconciliation model.** Repository and Figma adapters emit
  v2 operations directly; the installer synchronization coordinator is the sole
  lifecycle owner. The legacy parallel v1 propose/accept/apply runtime is retired.
- **Authority is enforced at application time.** Workspace-authoritative bindings
  export, external-authoritative bindings import, and shared-review bindings may
  do either after explicit selection.
- **Historical provenance no longer becomes a false live dependency.** Working
  artifact source pins remain causally accurate after an upstream revision moves;
  later drift is a visible non-blocking advisory, while stale current inputs are
  rejected before a skill writes.
- **Visualizations can own real review surfaces.** New visualization records may
  declare guarded local paths or HTTPS external locations such as Figma. Local
  companions are legal skill outputs, current v2 bindings verify external views,
  and downstream readiness waits for at least one verified surface rather than
  assuming every visualization is HTML.
- **Check passes are bound to workspace state.** New fast and browser results
  attest the checker-visible workspace snapshot. A reused pass becomes
  `not-run` when the workspace, checker identity, or attestation disagrees, and
  a suite refuses to attest if its inputs change while it is running.
- **Managed contracts have one integrity gate.** Doctor, `silver check`, and
  invocation preflight now use the same managed-file diagnostics. An altered
  framework-managed skill cannot be trusted to authorize its own invocation.
- **Audit provenance has one lifecycle.** Top-level acceptance is authoritative;
  source/input parity, design contexts, guidance, external binding pins,
  contributors, origin, and invocation timing are checked before writes. The
  deprecated nested acceptance value remains readable only when it agrees.
- **Trace and recommendations join exact results.** `silver trace` and
  `what-now` resolve results by output ID, kind, revision, and path, prefer the
  newest exact result deterministically, and expose duplicates or disagreements
  instead of silently combining unrelated history.
- **Launchers honor the workspace lock.** Generated POSIX and Windows launchers
  verify candidate versions in a defined order, skip older or malformed
  installations, prevent PATH recursion, warn before using a newer candidate,
  and fall back to the exact locked npm version.

## Upgrading

Run `silver migrate .` before synchronizing a workspace that still contains a
`silver/representation-binding/v1` file. Historical v1 results are left intact.
Create a fresh proposal with `silver sync inspect` before applying any change.

The native CLI embeds the check and synchronization runtime. Replacing copied
`.mjs` files does not update an installed executable; use a rebuilt 0.9.2 CLI or
installer package.

This repository prepares unsigned macOS packages for both supported
architectures. Signing, notarization, publication, and installation are separate
release actions.
