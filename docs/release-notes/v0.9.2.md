# Silver 0.9.2 — One Representation Model

This corrective release completes the representation-contract transition that
0.9.0 began. New linked-source and Figma synchronization now use the v2 binding,
change-set, result, and provider-operation contracts from inspection through
application. Historical v1 reconciliation records remain readable evidence,
but live v1 bindings must be migrated and inspected again before they can sync.

## Fixes

- **Representation checks understand v2 records.** Revision pins, synchronization
  states, semantic mapping, proposal freshness, and authority are evaluated from
  their v2 fields. Healthy initialized, uninitialized, and missing identities no
  longer produce false findings.
- **Proposal freshness is real again.** Pending proposals check every actionable
  operation even before a selection exists, including target absence, local
  sources, linked-source targets, and provider captures. Applied results are not
  compared against their intentionally pre-application identities.
- **There is one live reconciliation model.** Repository and Figma adapters emit
  v2 operations directly; the installer synchronization coordinator is the sole
  lifecycle owner. The legacy parallel v1 propose/accept/apply runtime is retired.
- **Authority is enforced at application time.** Workspace-authoritative bindings
  export, external-authoritative bindings import, and shared-review bindings may
  do either after explicit selection.
- **Historical provenance no longer becomes a false live dependency.** Working
  artifact source pins are immutable history: later availability or revision
  changes are not checked at all. Stale current inputs are still rejected before
  a skill writes.
- **Visualizations can own real review surfaces.** New visualization records may
  declare guarded local paths or HTTPS external locations such as Figma. Local
  companions are legal skill outputs, current v2 bindings verify external views,
  and downstream readiness waits for at least one verified surface rather than
  assuming every visualization is HTML.
- **Check passes are bound to workspace state.** New fast and browser results
  attest the checker-visible workspace snapshot. A reused pass becomes
  `not-run` when the workspace, checker identity, or attestation disagrees, and
  a suite refuses to attest if its inputs change while it is running.
- **Compiled checks and orientation use injected runtime dependencies.** The
  native CLI now supplies its contracts, representation checks, managed
  integrity, result index, and check attestation dependencies to fast checks
  and `what-now`; copied workspace scripts retain their portable fallback.
- **Managed contracts have one integrity gate.** Doctor, `silver check`, and
  invocation preflight now use the same managed-file diagnostics. An altered
  framework-managed skill cannot be trusted to authorize its own invocation.
- **Audit provenance has one lifecycle.** Top-level acceptance is authoritative;
  source/input parity, design contexts, guidance, external binding pins,
  contributors, origin, and invocation timing are checked before writes. The
  deprecated nested acceptance value remains readable only when it agrees.
- **New history is protected at write time.** Results are create-only, retries
  have new invocation IDs, duplicate output claims and same-revision rewrites
  are rejected, and working-artifact source pins must equal the producing
  invocation inputs. Lock enforcement horizons keep pre-0.9.2 records readable
  without letting them permanently fail current gates; use `silver check --since`
  for a read-only historical audit.
- **Trace and recommendations join exact results.** `silver trace` and
  `what-now` resolve results by output ID, kind, revision, and path, prefer the
  newest exact result deterministically, and expose duplicates or disagreements
  instead of silently combining unrelated history. Trace labels immutable
  artifact source pins separately from the producing invocation's live inputs.
- **Launchers honor the workspace lock.** Generated POSIX and Windows launchers
  verify candidate versions in a defined order, skip older or malformed
  installations, prevent PATH recursion, warn before using a newer candidate,
  and fall back to the exact locked npm version.
- **Browser checking is provider-neutral.** Chrome/Chromium remains the local
  deterministic default, while an explicitly selected MCP, CLI, or host-native
  browser can complete a state-bound inspection plan with normalized
  observations. Silver retains the check rules and never treats a provider's
  own success message as conformance evidence. Ego Lite is an optional CLI
  transport, not a replacement Chrome executable.

## Repairs to this release

0.9.2 is still unreleased; these are corrections made to it before it ships,
not a new version.

- **The audit enforcement horizon actually reaches green, and stays quiet.**
  `--since` and the horizon were two separate filters that both ran; a
  workspace with real history stayed permanently red and, once the horizon
  was adopted, printed its entire pre-horizon findings list as advisories on
  every single check. They are now one resolved cut-off: a pre-horizon record
  is skipped, not downgraded. `silver migrate --apply` reports the horizon
  once, when it is established or advanced, and only advances it past a point
  its own most recent passing check actually verified clean — never past
  records that were simply never examined. `artifact.artifact-sources-disagree`
  no longer inherits the producing record's age, since it inspects a live
  file that can still be wrong today. The three "-advanced" advisories
  (design-context, guidance, binding) are removed: they reported the passage
  of time against an immutable closed record and were never actionable;
  `silver trace` already surfaces the same drift per-artifact on demand.
- **provenance.sources is gone.** It was written to every result and artifact
  as a verbatim copy of the invocation's inputs, validated against those same
  inputs at write time, and checked again by `audit-trail.sources-disagree` —
  a field that was contractually required to be a duplicate carried no
  information, only a place to disagree. `artifact.sources` is unaffected: it
  lives in a separate file from the result that produced it, so comparing the
  two is a real cross-check, not a mirror.
- **Every subcommand answers `--help`/`-h`.** Previously only bare `silver`,
  `silver help`, and a few late-dispatch commands did; e.g. `silver check
  --help` silently ran a full check.
- **A visualization's own status decides whether a missing render is a
  defect.** A `draft` visualization can declare a render before the file
  exists — that's work in progress. `active`/`accepted` visualizations are
  held to the standard the checks already enforced; `rejected`/`stale`/
  `archived` remain exempt.
- **One word for one concept.** `payload.views[]` is `payload.renders[]`;
  `role: review-surface` is `role: render`; the `view-provenance` check is
  `render-provenance`. `payload.view_path` is untouched — it shipped in
  0.9.0/0.9.1 and stays as permanent legacy shorthand, not scratch work from
  this cycle.
- **Four schemas with no remaining reference are deleted**: `change-set`,
  `provider-operation`, `reconciliation-result`, and the v1-shaped
  `representation-binding` (superseded by `representation-binding-v2`, which
  was already the only one anything read).
- **A token that no longer resolves is now a finding, not silence.**
  `semantic-styles` previously only caught new raw literals; a `var(--ds-*)`
  reference to a token the design system removed or renamed produced nothing.
  It's checked against the compiled `tokens.css` now, and the finding —
  along with the existing raw-color/raw-dimension findings — names the skill
  to re-invoke when the artifact has one. `what-now` does the same for any
  failing check's findings: a conformance issue under `prototypes/`,
  `design/work/visualizations/`, `presentations/`, or `production/` surfaces
  as its own `prototype`/`visualize`/`pitch`/`implement` recommendation
  alongside the generic "run design-check" one, rather than only the latter.
  This surfaced three tokens the framework's own bundled renderers referenced
  but the design system never declared (`--ds-surface-canvas`,
  `--ds-layout-content-max-width`, and `--ds-layout-card-min-width`) — fixed
  by renaming the first two to the tokens they meant (`--ds-surface-page`,
  `--ds-layout-container-max-width`) and declaring the third for real.
- **`silver migrate --apply` and `silver update` check themselves on the way
  out.** Both used to leave a workspace's design content unexamined after
  changing its schemas — nothing ran until someone remembered to check by
  hand. They now run the fast suite immediately afterward (skipped for a
  `migrate` preview, which never touches the real workspace) and print a
  `silver what-now .` nudge when it isn't clean. The fast suite's own status
  never changes `migrate`/`update`'s exit code; that stays keyed to whether
  the schema change itself succeeded.

## Upgrading

Run `silver migrate .` before synchronizing a workspace that still contains a
`silver/representation-binding/v1` file. Historical v1 results are left intact.
Create a fresh proposal with `silver sync inspect` before applying any change.

Run `silver migrate . --apply` once on an existing 0.9.2 workspace as well: it
records the audit-enforcement horizon required for historical results to satisfy
current gates.

The native CLI embeds the check and synchronization runtime. Replacing copied
`.mjs` files does not update an installed executable; use a rebuilt 0.9.2 CLI or
installer package.

For an optional browser transport, run `silver tools --list` to find its
provider ID. Use `silver check --browser --browser-provider <id> --prepare`,
complete the returned plan in that provider, and supply its
`silver/browser-check-observation/v1` file with `--complete`. An explicit
provider never silently falls back to Chrome.

Ego Lite is the one shipped CLI adapter: when it is installed and explicitly
selected, Silver uses an isolated Ego task space, captures the same normalized
measurements, and closes that task space afterward. MCP and host-native tools
remain agent-owned and therefore use the prepare/complete handoff.

This repository prepares unsigned macOS packages for both supported
architectures. Signing, notarization, publication, and installation are separate
release actions.
