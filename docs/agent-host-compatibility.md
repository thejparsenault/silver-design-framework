# Agent Host Compatibility

Silver's artifacts are agent-neutral: `.skills/` holds the canonical skill
packages and `AGENTS.md` is the canonical entry point. Neither is discovered
automatically by every host. This document records what each supported host
actually reads, what Silver generates to bridge the gap, and which hosts are not
yet supported.

Adapters are **generated, never canonical**. They are recorded in
`.silver/lock.yaml` as managed files, regenerated by `silver repair`, and safe to
delete. Removing every adapter leaves a complete, working Silver workspace for
any agent that reads `AGENTS.md` and `.skills/`.

## Claude Code — supported

Claude Code reads `CLAUDE.md` and does **not** read `AGENTS.md`. It discovers
skills only under `~/.claude/skills/`, `.claude/skills/`, and plugins. A
workspace that stops at `AGENTS.md` and `.skills/` is invisible to it.

Silver generates three adapters at setup, migration, and repair:

| Adapter | Purpose |
| --- | --- |
| `CLAUDE.md` | Imports `@AGENTS.md` plus a short Silver preamble. Merged into a marked block so a project-owned `CLAUDE.md` keeps its content. |
| `.claude/skills/<id>` | Relative symlink to `../../.skills/<id>`. Claude Code follows symlinks in project skill directories and reads `SKILL.md` from the target. Falls back to a copy when symlink creation fails. |
| `.silver/bin/silver` | Launcher that execs the CLI. Gives the workspace one stable command regardless of how the CLI is delivered. |

Each `SKILL.md` declares `allowed-tools` for the launcher so bundled operations
do not prompt every turn. `${CLAUDE_SKILL_DIR}` substitution inside
`allowed-tools` requires Claude Code v2.1.129 or later; on earlier versions the
rule simply never matches and the command still prompts.

### Known friction

- Silver's skill ids are generic. `map`, `system`, `research`, `component`, and
  `implement` can shadow, or be shadowed by, a personal or bundled skill of the
  same name. `silver doctor` reports this as `info`; Silver does not rename its
  skills to avoid it.
- The launcher records an absolute path to the Silver installation, so it is
  machine-specific. A teammate on another machine runs `silver repair` once.
  `silver doctor` reports a launcher pointing at a path that no longer exists.

## Claude Cowork — not yet supported

Cowork differs from Claude Code in three ways that matter:

1. It loads only the skills enabled for the claude.ai account, uploaded as ZIP
   files. There is no folder-based skill discovery, so `.claude/skills/` and
   `.skills/` are both invisible.
2. It does not read `CLAUDE.md` or `AGENTS.md`.
3. Shell commands and code run in an isolated environment on Anthropic's
   servers, reaching local files through the Claude Desktop app. Node
   availability there is unverified, and a Silver installation is not present.

Silver's only sanctioned way to produce a durable output is a guarded Node
invocation. That makes Cowork an architectural gap rather than a missing
adapter. Support requires two things Silver does not have:

- **A Node-free durable-output path.** Every skill would need a way to write a
  provenance-carrying artifact using plain file operations, with the guarded
  runtime as an optional upgrade rather than the only route. This revisits the
  invocation contract that 0.5 and 0.6 are built on.
- **An uploadable Silver skill package.** One ZIP that teaches Claude the
  workspace model and points it at `design/manifest.yaml`, `AGENTS.md`, and
  `.skills/<id>/SKILL.md` as files to read.

Until both exist, a Cowork user can read and edit a Silver workspace's artifacts
as ordinary files, but cannot run guarded invocations, record skill results, or
produce checked output.

## Other hosts

Any agent that reads `AGENTS.md` and can run a shell command works without an
adapter. Codex and other hosts that use their own instruction-file conventions
would each need a generated adapter following the Claude Code pattern; none is
implemented.

## Adding a host adapter

Adapters live in [`installer/agent-adapters.mjs`](../installer/agent-adapters.mjs).
A new one needs:

1. A render function producing deterministic content, and a merge function if
   the target file may be project-owned.
2. Wiring into `setupWorkspace`, `repairWorkspace`, and the migration.
3. A `doctor` diagnostic at `warning` level — adapters are repairable, so a
   broken one must never block canonical design work.
4. Coverage in `installer/tests/agent-hosts.test.mjs`.

Never make an adapter a prerequisite for a skill. If `.claude/` were required to
run a skill, Silver would stop being agent-neutral.
